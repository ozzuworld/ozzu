## Agent Behavior Observations

### What Worked Well
1. **Code quality** — Cipher writes clean, well-structured code. The logger module (47 lines) and dashboard (108 lines) were production-ready on first attempt.
2. **Codebase understanding** — Cipher correctly found existing patterns (e.g., notification format from planned→approved transitions) and followed them.
3. **Quick directives** — After prompt fix, quick directives consistently commit, push, and mark complete.
4. **Explore directives** — The code review was thorough and found a real bug I introduced.
5. **Commit quality** — Clear commit messages with Co-Authored-By after prompt update.

### What Failed
1. **Concurrent agents conflicts** — Two agents editing the same file simultaneously: one agent committed the other's changes alongside its own. Solution: added git stash warning to prompts, but true fix would need file-level locking.
2. **Bridge restart self-kill** — Agents that restart the bridge kill themselves (they run as children of the bridge process). Solution: added warning to prompt. True fix would need agents to run outside the bridge container.
3. **Agent logs empty** — `claude -p` buffers stdout until exit, so piped logs only show the final output. The agent's work during execution is invisible.
4. **Crashed agents** — 2/10 agents crashed mid-work (exit non-zero). The recovery pipeline (reset to stale → auto-retry) mostly worked, but the failure tracking agent's crash went undiagnosed because logs were empty.
5. **Explore type didn't auto-transition** — Had to manually PATCH to "planning". Fixed: now auto-transitions like quick.

### Prompt Engineering Changes (3 iterations)

**Iteration 1 — Quick directive commit fix:**
- Root cause: quick directives used `buildPlanningPrompt()` which had no commit/push instructions
- Fix: added full implementation checklist to planning prompt for quick type
- Result: agents now consistently commit and push

**Iteration 2 — Troubleshooting patterns:**
- Added: file search before writing, error reading, git conflict handling
- Added: bridge restart awareness (don't restart if you'll die)
- Added: concurrent edit awareness (check git status, use stash)

**Iteration 3 — Final polish:**
- Added: explore directive instructions (research + report, no commit)
- Added: Co-Authored-By in commit template
- Consolidated quick/explore handling into single `isImmediate` path

## Remaining Issues

1. **Agent output logging** — Need a way to stream claude CLI output during execution, not just at exit. Options: structured status updates via bridge API (already in prompt), or use `--output-format stream-json`.

2. **Concurrent edit safety** — Prompt warnings help but aren't reliable. Consider: sequential agent execution (queue), or file-level locks in the bridge.

3. **Feature directive flow untested** — All test directives were "quick" type. The full planning → PIN approval → implementation flow wasn't tested this session.

4. **Agent debugging** — When an agent crashes, there's no way to see what it was doing. Need either: streaming log output, or the agent should POST its progress to /status more frequently.

5. **Bridge restart coordination** — Agents modifying bridge code need to coordinate restarts. Current workaround: commit+push before restart. Better: separate agent runtime from bridge process.
